# 验证说明

验证日期：2026-10-20。输入与卡片均为自编的 LumaBox 虚构资料，不是用户私人课件。

## 实际执行

Agent 阅读了四页 PDF 的抽取文字，并查看四页渲染图。第 4 页只有图片，抽取文字为零；预处理将其标记后，由 Agent 看图转录到 `scan-transcription.md`。随后列出知识点、生成 12 张卡并对照来源复核。

使用 Anki 官方 Python 后端 26.9.3，在新建隔离 collection 中实际导入示例包，得到 12 notes / 12 cards；其中 10 张 Basic、2 张 Cloze，1 张扫描页图片作为背面证据。重复导入不新增重复卡；修改答案后保持 GUID，在测试库设置 always update 后更新原 note。整个过程没有打开用户真实 Anki 数据。

## 可复跑检查

执行 `python tests/checks.py`，在新建临时目录内运行下列 16 项检查：

1. 拒绝越界来源页码。
2. 拒绝缺少来源证据的卡。
3. 拒绝重复题干。
4. 拒绝 included 概念没有对应卡。
5. 拒绝多个 Cloze 目标。
6. 拒绝读取 cards.json 目录之外的媒体。
7. 保留已有输出目录，不覆盖。
8. 对双问题发出原子化警告。
9. 保留数学运算符和大小写区别，转义 HTML 特殊字符。
10. 标记扫描页并渲染所有页。
11. 修改答案后保持 GUID。
12. 实际导入 Anki 后端为 12 notes / 12 cards。
13. 问答/填空正面可见文字不泄漏答案。
14. 图片导入后字节一致。
15. 重复导入不新增重复卡。
16. 修订答案更新原 note。

另由导出器检查 ZIP/SQLite 完整性、媒体、GUID、数量、孤立卡片与新卡复习状态。发布检查的实际输出见 [结果 JSON](verification-results.json)。

## 结果的含义

这些检查证明本示例及导出功能在测试环境中工作，不证明所有学科、所有扫描件或所有 Agent 都能生成同样质量的卡。内容复核由同一 Agent 完成，未做独立学习者或教育效果评估。

资料明确未提供“最大吞吐量具体数值”。该点进入 blocked，没有捏造卡片，所以示例 audit 为 `PARTIAL_SOURCE_COVERAGE`。这代表来源缺口，不是文件损坏。完整规则中的选择题和图片遮挡是制卡指导；当前脚本只原生生成 Basic 和单空 Cloze，图片可以作为辅助媒体。
